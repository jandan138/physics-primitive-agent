<PaperBlock
  id="background-p003"

  original="Quadrics have also been adapted to handle approximation of meshes as a linear interpolation of spheres [sqem, anim_sqem]. Instead of the standard quadric metric, a newly proposed quadric metric is based on the signed distance to a sphere: $d = n^top (p - c_sphere) - r_sphere$. From this formulation, an approach that solves for the center $c_sphere$ and radius $r_sphere$ is derived, and elements can be merged together in a similar way as standard quadrics. Unlike standard quadrics though, the cost function is replaced with the sum of squared oriented distances of each sphere to the faces of the vertices that it subsumes. Spherical Quadrics (SQEM) lead to a coarse approximation of the input mesh as an interconnected series of spheres, which can then be used for animation. Because of its simplicity and similarity to our goal of abstracting an input with coarse shapes, we draw inspiration for our approach from Spherical Quadric Error Metrics. Note that SQEM is not comparable to our method in rigid body simulation, since the parameters of spheres are linearly interpolated along mesh faces and edges and thus it cannot be represented as discrete components for collision."

### Shape Abstraction

<PaperBlock
  id="background-p006"
  section="Related Work"
  original="Another approach to simplifying meshes is abstraction using simpler geometric primitives. Geometric primitives, often represented as parametric models such as signed distance functions, quadrics, or explicit primitives, are used in constructive solid geometry for computer aided design [realtime_csg] along with parametric curves [abstraction_of_shapes]. There are a number of different approaches to recovering shapes from input meshes such as random sampling (RANSAC) [efficient_ransac, generic_primitive_detection_in_point_clouds] and data-driven approaches [cuboid_abstraction, superquadrics, marching_primitives, surface_edge_detect_point_cloud]. These approaches primarily work on simple inputs and cannot preserve high frequency details. One work related to our approach is [quadric_surface_extraction], which fits quadrics to a surface with Lloyd's algorithm and a Euclidean distance metric. Their fitting also requires the computation of eigenvectors to fit quadrics, distinct from our approach which uses them for alignment only. A number of works stemmed from that work [variational_3d_shape_segmentation]. Another similar work is [hierarchical_mesh_segmentation_based_on_fitting] which seeks to perform shape approximation by merging faces, similar to our approach. In contrast though, this prior work only shows 3 shapes with custom cost functions per shape (whereas this work shows 6 with the same cost function), and is not guaranteed to enclose the input shape. Furthermore, that work does not have a specific target application and tested on a much smaller dataset, whereas this work has a large emphasis on validation specifically for collision detection."

### Approximate Convex Decomposition

<PaperBlock
  id="background-p008"
  section="Related Work"
  original="Prior work on convex decomposition for collision detection has revolved around approximate convex decomposition [model_composition_from_interchangeable_components, vhacd, nav_approx_acd, acd_polyhedra, animated_decomp, shape_segmentation_by_approx_convex, hierarchical_convex_approximation_of_3d_shapes]. Approximate convex decomposition relies on splitting an input mesh into convex hulls, approximating the shape of the input mesh using a concavity metric to determine whether to a split a shape into subparts. Many of these approaches remesh or voxelize the input to make it manifold, then partition the manifold mesh top-down along cutting planes, tightly matching the input shape. What we found when investigating whether this approach is suitable for game development is that convex hulls are more complex than the count of hulls indicates, can occasionally be imprecise, and are not easy to modify within existing DCC tools or engines while maintaining convexity. This motivates our divergence from convex hull decomposition."
  translation="面向碰撞检测的凸分解既有工作主要围绕近似凸分解展开 [model_composition_from_interchangeable_components, vhacd, nav_approx_acd, acd_polyhedra, animated_decomp, shape_segmentation_by_approx_convex, hierarchical_convex_approximation_of_3d_shapes]。近似凸分解依赖于将输入网格拆分为凸包，并使用凹度指标近似输入网格的形状，以判断是否应将某个形状拆分为子部分。许多此类方法会对输入重新网格化或体素化，使其成为流形，然后沿切割平面自顶向下划分流形网格，从而紧密匹配输入形状。我们在考察这种方法是否适合游戏开发时发现，凸包的复杂度高于凸包数量本身所显示的程度，偶尔可能不够精确，并且在现有 DCC 工具或引擎中不易修改同时保持凸性。这促使我们偏离凸包分解路线。"
