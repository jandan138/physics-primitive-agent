\section{Experiments}
\label{sec:experiments}

We report the recorded five-asset Phase~0 slice and one Franka smoke asset.
The experiments answer three bounded questions: when does package context change a geometry-plausible primitive, do generated baseline packages fail only after successful Newton mapping, and what extra ownership condition appears for articulated assets?

\subsection{Mechanism study: capped bed versus Franka cylinders}
\label{sec:exp-mechanism}

For the recorded capped scope, the bed selected-cylinder package fails drop/settle with residual final speed about $0.082$\,m/s, while a recorded Franka cost-guided cylinder package passes with about $0.00071$\,m/s.
The same target bed cylinder passes as an isolated primitive; the failure is a full-compound package effect.
COM/inertia sensitivity is the strongest supported mechanism; mass alone and contact/floor are rejected as sole explanations in the recorded diagnostic checks.
Figure~\ref{fig:bed-franka-mechanism} summarizes the mechanism evidence.
The important point is not that cylinders are generally bad.
The recorded Franka package contains small link-local cylinders and passes its bounded task smoke,
while the bed case fails only when the large flat primitive participates in the full compound body.
This supports the main separation between a candidate shape and an accepted simulation artifact.

\subsection{Diagnostic guard}
An opt-in package body-state guard falls back only the flagged capped bed package while keeping the unflagged Franka cylinder package in the recorded Newton task smoke.

\subsection{Collision-only throughput microbenchmark}
In one bed-aligned pressure scene with 32 accepted box primitives versus 32 convex64 mesh proxies, native primitives report median $2.21\times$ generated contacts per collide call and about $5.3\%$ lower collision-only wall time.
This is scoped collision-pipeline evidence, not a full-simulation speedup claim.

\subsection{Phase 0 rigid-asset diagnostic table}
Table~\ref{tab:phase0-grscenes-rigid} summarizes the current scoped Phase~0 rigid run over five materialized GRScenes assets.
The run records first-mesh bounding-primitive, CPD-style, and CoACD convex-mesh candidate lanes with Newton contact, drop/settle, stack-or-slide, and sphere-rain probes.
It also records V-HACD runtime evidence for all five assets, with V-HACD probe failures on the container, contact-affordance, and stackable rows.
We treat these V-HACD failures as recorded diagnostic outcomes: the packages are generated and mapped, but the Newton task probes reject them, illustrating why candidate generation and Newton task acceptance must be reported separately.
It also includes one Franka link-aware package generation record, one Franka USD articulation smoke, and one generated-package Franka task smoke.
It is not a complete Phase~0 benchmark: the asset set is small, robot generated-package checks currently cover only one Franka smoke asset, and the task suite does not cover manipulation or broad articulated dynamics.

Figures~\ref{fig:phase0-overlays} and~\ref{fig:phase0-control-overlays} show why a table alone is insufficient.
Each row starts from default/render mesh prims loaded through the repo-local USD mirror, then shows the
candidate package geometry that the diagnostics consume.
The container, contact-affordance, and stackable rows are especially informative: all three have V-HACD hull packages, so
the later failures are not dependency gaps or missing-baseline artifacts.
They are mapped collision packages that fail particular Newton probes.
The keyboard row is retained as a precision negative control: routine probes pass, but the recorded
policy still routes the asset to manual review rather than promoting it as a solved collider.

\subsection{Collision-probe scene renderings}
\label{sec:exp-collision-scenes}

Figure~\ref{fig:phase0-collision-scenes} renders the diagnostic context for the three most
evidence-bearing rigid assets.
The left column shows the V-HACD package that was generated and mapped.
The middle column summarizes the drop/settle state transition using recorded initial and final
heights, and the right column summarizes the stack-or-slide probe.
For the bowl, both drop/settle and stack/slide reject the V-HACD package.
For the cylindrical contact prop and tray, the V-HACD stack/slide probe passes while drop/settle still rejects the
package.
That split is useful: the checker is not a blunt baseline filter.
It localizes which physical task failed and leaves passing probes visible.

\begin{figure}[H]
  \centering
  \includegraphics[width=0.92\textwidth]{figures/generated/phase0_collision_probe_scenes.pdf}
  \caption{Collision-probe scene visualizations for the recorded V-HACD lanes on the container, cylindrical contact prop, and stackable tray rows. These panels are deterministic diagnostic renderings from the Phase~0 report, not photorealistic evidence. The key point is that a generated and mapped package can pass one task while failing another.}
  \label{fig:phase0-collision-scenes}
\end{figure}

The collision-scene panels also show why the V-HACD failures carry useful evidence.
If V-HACD had failed to run, the comparison would only show an engineering dependency gap.
Here the generated packages exist, map into Newton shapes, and then fail named probes.
This separates dependency failures from task-level rejection and motivates reporting probe-specific
labels rather than a single geometry-generation success rate.

\subsection{Failure labels and measured symptoms}
\label{sec:exp-failure-labels}

Table~\ref{tab:phase0-failure-labels} lists the recorded failure rows behind the red cells in
Figure~\ref{fig:phase0-outcome-matrix}.
The labels are not post-hoc prose annotations; they are emitted by the probe code from measured
state.
For example, the bowl V-HACD drop/settle row records \texttt{no\_descent},
\texttt{not\_settled}, and \texttt{floor\_breach} together with a final speed of
$5.493$\,m/s.
The same bowl V-HACD package then fails stack/slide because the probe moves $1.219$\,m across the
support.
The cup V-HACD package shows a different failure: the final height is close to the plane, but the
final speed still exceeds the settle gate.
The tray V-HACD row is again different: the stack/slide probe accepts the package, while
drop/settle rejects it for residual motion.
This heterogeneity motivates reporting named probes instead of a single binary baseline score.

\subsection{Franka articulation smoke}
In the Franka smoke run, the USD smoke asset provides the articulated test case.
The link-aware package generator detects 12 rigid-body links and 12 joint edges, emits 12 link-framed box primitives, and records zero cross-link merges.
The \texttt{panda\_link8} primitive is an explicit meshless sentinel because that link has no mesh in the source USD mirror.
The articulation smoke records joint-tree import, a short gravity hold, and a simple kinematic trajectory as passed.
The generated-package task smoke separately suppresses source USD shapes, attaches all 12 generated package primitives to Newton bodies, records zero missing body links, and passes the same short hold/trajectory probe.
This is generated-package consumption evidence for one Franka smoke asset, not whole-robot collider quality or manipulation evidence.

\begin{figure}[tbp]
  \centering
  \includegraphics[width=0.98\textwidth]{figures/generated/franka_link_aware_rtx_task_scene.pdf}
  \caption{RTX view of the single Franka link-aware generated-package smoke. The visual plate shows the recorded link-framed package in the Newton task context with source USD collision shapes suppressed, 12 generated box primitives attached to 12 detected links, zero missing body links, and 66 generated self-collision filter pairs for the smoke configuration. This supports bounded package-consumption exposition only; it is not whole-robot collision-quality or manipulation evidence.}
  \label{fig:franka-task-scene}
\end{figure}

Primitive packages for articulated assets must preserve link identity, because a visually plausible
whole-robot proxy can be unusable if it merges geometry across joints.
The link-boundary check therefore runs before task execution: every primitive must
have one source link, use that link as its frame, and avoid cross-link merges.
The subsequent generated-package task smoke then records package consumption by Newton bodies with
source USD collision shapes suppressed.
The recorded task has a short gravity hold and a simple trajectory only; it is a consumption and
boundary smoke, not manipulation evidence.
