\section{Method}
\label{sec:method}

Our diagnostic acceptance loop has four stages: (i)~import asset provenance and link structure; (ii)~generate or import primitive candidates from heuristics, native lanes, or decomposition outputs; (iii)~run Newton diagnostics; (iv)~promote, reject, or fallback with a recorded reason.
The central design choice is to keep \emph{candidate generation} and \emph{simulation acceptance} as separate artifacts.
Geometry methods propose packages; the acceptance layer decides whether a package survives a named Newton task under recorded settings.

\paragraph{Candidate generation.}
Each asset is first normalized into a package manifest that preserves source asset identity, stage path, units, and, when present, USD link boundaries~\cite{openusd2026}.
Rigid assets can receive bounding primitives, native primitive lanes, CPD-style primitive packages~\cite{cpd2026}, and convex-mesh baselines such as CoACD and V-HACD~\cite{coacd2022,vhacd}.
For articulated assets, candidate generation is link-framed: a primitive is emitted under the link that owns its source geometry, and the package records whether any primitive crosses a joint boundary.
Candidate quality is summarized by primitive or hull count, geometric residual when available, and editability.
These are descriptors of the hypothesis, not acceptance signals.
The Phase~0 implementation keeps four generated rigid lanes visible in the paper: a first-mesh
bounding primitive, a CPD-style primitive package, a CoACD convex-hull package, and a V-HACD
convex-hull package.
The single-convex-hull lane is retained as a fallback accounting lane even when it is not promoted
as a generated primitive package.
This distinction matters for interpretation: a generated package can be a successful candidate and
a failed simulator artifact in the same row.

\paragraph{Acceptance layer.}
The acceptance layer converts each candidate package into a Newton task scene and records an outcome with configuration, seed, and package metadata~\cite{newton2026}.
Body-state and drop/settle gates label residual speed and compound COM/inertia risk.
Contact probes observe false clearance, blocked openings, excessive contact counts, and stack-or-slide behavior.
For robots, a link-boundary check forbids cross-link merges before the package enters an articulation smoke; the generated-package task smoke then checks whether Newton consumes the emitted link-framed primitives in the bounded hold/trajectory path.
Each probe emits an outcome from a small vocabulary: \emph{accept}, \emph{failure},
\emph{fallback}, \emph{not applicable}, or \emph{dependency gap}.
The categories are intentionally not collapsed into one score.
\emph{Accept} means the package survived the task; \emph{failure} means it was available and mapped but produced a named runtime label; \emph{fallback} means the lane was routed away explicitly; \emph{not applicable} keeps rigid and robot probes from being misread as each other.

\paragraph{Probe scenes.}
The diagnostic scenes are intentionally small and fixed by configuration.
The drop/settle scene places the package above a static plane and records descent, contact,
floor breach, final support height, and final linear speed.
The stack-or-slide scene treats the package as the support, places a small probe box above it, and
records final contact, horizontal displacement, probe height, and support breach.
The sphere-rain scene uses a fixed set of small probes to stress contact coverage without turning
the run into a full manipulation benchmark.
The scenes are small by design: they are repeatable stressors that expose when a plausible proxy becomes unusable for a specific physical question.

\paragraph{Fallback policy.}
Failed packages route to another candidate lane, a convex-mesh fallback, SDF, or manual review depending on configuration.
Fallback remains in the report because it is part of the acceptance decision, not an omitted experiment.
An opt-in package body-state guard can fallback only flagged packages while preserving unflagged packages in the same task smoke, as recorded for capped bed versus Franka cylinders.
This keeps fallback accounting conservative: accepted primitive packages remain native and inspectable, while rejected packages retain a reproducible reason.

\paragraph{Evidence registry.}
Quantitative statements in this manuscript are backed by the shared \texttt{claims.yaml} registry and dated records under \texttt{docs/records/}.
The figures follow the same rule: they visualize recorded Phase~0 reports and asset mirrors, but do not add unrecorded evidence.
